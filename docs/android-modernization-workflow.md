# Android Modernization Workflow

Use this workflow for Android maintenance branches under `upgrade/wallet-modernization`.

## Branching

- Start from `upgrade/wallet-modernization`.
- Create one mini-branch per topic, for example `feature/bem-37-sentry-warning-audit`.
- Commit only after validation.
- Merge back locally with `git merge --no-ff`.
- Do not push unless explicitly approved.

## Java

Use JDK 17 for local Android work:

```powershell
$env:JAVA_HOME = 'D:\tmp\jdks\temurin17\jdk-17.0.19+10'
```

The Android Gradle runner checks `JAVA_HOME\bin\java.exe` before falling back to `java` from `PATH`. The AGP 8.13 baseline requires JDK 17.


`android:dev:smoke:*` helpers use `ANDROID_SMOKE_UI_DUMP_TIMEOUT_MS` for `uiautomator dump` calls. This timeout is intentionally shorter than the global ADB command timeout so non-idle Android UI states, including repeated Electrum TLS retry loops, fail with a bounded smoke summary instead of leaving long-running helper processes behind.

APK installation uses `ANDROID_SMOKE_INSTALL_TIMEOUT_MS`, defaulting to at least `180000` ms, because the current RN `devDebug` APK is large enough that a 60-second global ADB command timeout can interrupt a valid streamed install and force an unnecessary ADB server restart.

The same helpers force-stop and uninstall the existing test package, fall back through `pm uninstall --user 0` and `pm clear` when needed, and run `pm trim-caches 2G` before the `/data` storage preflight unless `ANDROID_SMOKE_UNINSTALL_BEFORE_INSTALL=false` or `ANDROID_SMOKE_TRIM_CACHES_BEFORE_PREFLIGHT=false` is set. This keeps repeated runs deterministic for the current large RN `devDebug` APK: a previous smoke install or stale package cache cannot consume enough emulator storage to fail the next preflight before the fresh APK is installed. Smoke summaries record the package cleanup path so a future AVD-specific uninstall failure is visible instead of hidden.

The reduced dev no-network smoke wrappers set `ANDROID_SMOKE_DATA_STORAGE_MULTIPLIER=2.5` so the controlled external-network blocker proof can run on the current API 36 AVD after uninstall and cache trim. The default full dev smoke helper keeps the stricter `3` multiplier and must remain the dashboard/runtime proof before app behavior is called ready.

`android:dev:release:verify-local` validates the Android release package paths without local Sentry upload credentials, checks the generated summary and APK manifests, and scans the generated DEX packages for the secure-storage backend contract. Its build step sets `SENTRY_DISABLE_AUTO_UPLOAD=true`, cleans generated React bundle/assets/resource/sourcemap outputs for each requested release variant before rebuilding it, builds `devRelease`, `stageRelease`, `prodRelease`, and `betaRelease`, and writes `local-docs/android-release-dev-summary.txt` with per-variant APK size, release JS bundle size, release source-map size, SHA-256 evidence, Gradle attempt counts, bounded retry metadata, and a line-ending-normalized fingerprint of the release inputs that affect Android package generation. The per-variant generated-output cleanup keeps RN Gradle plugin release assets deterministic across repeated local release validations. The release runner retries a Gradle task only for configured known transient native-build exit codes, currently the Windows CMake/Ninja `1073807364` case; successful summary validation still requires the final variant exit code, APK existence, release JS bundle existence, valid source-map JSON, byte counts, SHA-256 digests, and manifest output to be valid. `android:dev:release:check-summary` verifies that each recorded APK, release JS bundle, and release source map path exists, byte count matches the file, SHA-256 matches the actual file digest, retry metadata is present and internally consistent, and the recorded release-input fingerprint still matches the current repo across LF/CRLF working-tree normalization. `android:dev:release:check-apk-manifest` reads the generated APKs with `aapt2` and verifies the package IDs, version, min/target/compile SDK levels, and Android 13 notification permission in the actual release artifacts while reading Gradle expectations from the same project root being audited. `android:dev:release:check-secure-storage-apks` reads the same APK paths with `apkanalyzer dex packages`, requires `com.oblador.keychain.KeychainModule`, and rejects the removed `com.reactlibrary.securekeystore`, `RNSecureKeyStorePackage`, and `RNSecureKeyStoreModule` markers in every requested variant. Override the default set with `ANDROID_RELEASE_VARIANTS=dev,stage,prod,beta` when a branch intentionally narrows or extends release validation. This proves release bundling, source-map generation, manifest output, native secure-storage packaging, and APK generation only; Sentry source-map upload remains blocked until `sentry.properties` or equivalent Sentry env values are available.

`android:upload-signing:audit` checks the ignored `android/keystore.properties` file or the four `GOLDWALLET_UPLOAD_*` environment variables without writing password values to its local summary. Existing properties and keystore paths are canonicalized; sensitive files inside the repository must be untracked and confirmed by `git check-ignore`, while paths outside the repository are accepted without exposing their location. The keystore must be a regular file, so a directory or other non-file path cannot pass readiness. A partial or unsafe configuration fails before Gradle; `android:prod:bundle:signed` additionally sets `goldwalletRequireUploadSigning=true`, removes stale AAB output, compares the configured alias certificate fingerprint with the certificate embedded in the rebuilt AAB, and validates the bundle with pinned official `bundletool`. It then generates a debug-key installable universal APK from that exact signed AAB, requires `PAGE_ALIGNMENT_16K`, validates APK ZIP alignment plus every `arm64-v8a` and `x86_64` ELF `LOAD` segment at `0x4000` or greater, runs the embedded production smoke, and binds the AAB, universal APK, and smoke summary by SHA-256. `android:upload-signing:proof` generates an ignored random PKCS12 key, exercises that same full runner, and removes the temporary keystore.

Use the dedicated runtime proof on an API 36 `google_apis_playstore_ps16k` AVD before calling the Android candidate 16 KB-runtime ready:

```powershell
$env:ANDROID_SERIAL = 'emulator-5556'
corepack yarn android:16kb:runtime:verify
```

The runner checks `adb shell getconf PAGE_SIZE` before building and requires exactly `16384`. It then exercises the local signing proof, installs the universal APK generated from the exact signed `prodRelease` AAB, and requires the smoke summary to retain the same AAB/APK digests and observed runtime page size. It writes `local-docs/android-16kb-runtime-proof-summary.txt`; `android:16kb:runtime:check-summary` revalidates the runtime size, serial, exact artifact paths, byte counts, and SHA-256 digests, so a later ordinary signing proof that overwrites those artifacts invalidates rather than silently replacing the 16 KB evidence. A regular 4 KB AVD fails before Gradle starts. On Windows, run the native release build from a physical short worktree such as `D:\w940`; a junction to a long canonical worktree does not reliably prevent Ninja object paths from exceeding the 260-character limit. The proof validates repository signing, 16 KB artifact alignment, and execution on a 16 KB kernel. Real upload-key custody, Play App Signing enrollment, upload acceptance, Sentry delivery, and rollout remain external release checks.

`android/release-version.properties` is the single Android `versionCode`/`versionName` source consumed by Gradle, APK manifest checks, AAB validation, signing proof, and production signed-bundle evidence. `android:release-version:audit` compares that candidate with the public Play baseline in `android/play-release-baseline.json` and the latest authoritative Play Console code supplied through `GOLDWALLET_PLAY_LATEST_VERSION_CODE`; its generated summary remains valid while reporting `Production release version ready: no`. The public listing observed on 2026-07-16 reports `6.5.2`, so the current repository candidate `6.5.1 (14)` is intentionally blocked from production signing until release ownership chooses a newer semantic version and provides the latest Play Console `versionCode`. The production signed-bundle runner also dumps the generated base manifest with pinned `bundletool` and requires exact candidate metadata. Local signing proof bypasses only store monotonicity and still validates the AAB metadata match.

The Google Play internal handoff uses the pinned official `@googleapis/androidpublisher` `36.0.0` client and the [Android Publisher v3 edit workflow](https://developers.google.com/android-publisher/api-ref/rest). `android:play:internal:dry-run` is network-free/read-only and writes a secret-safe readiness summary. `android:play:internal:validate-upload` requires the release-version gate, real upload-signing readiness, and `GOLDWALLET_PLAY_SERVICE_ACCOUNT_JSON`; an in-repo credential file must pass `git check-ignore`, and the local preflight rejects unreadable or malformed JSON, missing Google Auth service-account fields, and an invalid or non-RSA private key without printing credential values. This is structural validation only; account activity and Play access are not claimed until the live edit validates. After those local preconditions, it runs the live strict Electrum release gate, builds the signed AAB, and requires the candidate-bound emulator/16 KB artifact summary before authenticating with Google. Only then does it insert an edit, [upload the bundle](https://developers.google.com/android-publisher/api-ref/rest/v3/edits.bundles/upload), update the `internal` track, validate the edit, and delete it, including best-effort cleanup after failures. `android:play:internal:commit` additionally requires an exact `GOLDWALLET_PLAY_COMMIT_CONFIRMATION=io.goldwallet.wallet:<versionCode>:internal:<status>` before it can commit. The workflow exposes no production-track or backend-gate bypass and writes no service-account path, email, key, token, or API edit identifier to its summary.

Useful smoke overrides:

- `ANDROID_SERIAL`: select a specific emulator/device from `adb devices`.
- `ANDROID_SMOKE_APK`: install a non-default APK path.
- `ANDROID_SMOKE_PACKAGE`: launch a non-default package name.
- `ANDROID_SMOKE_WAIT_MS`: non-negative milliseconds to wait before reading startup logs; default is `20000`.
- `ANDROID_SMOKE_UI_WAIT_MS`: non-negative milliseconds to poll UI hierarchy for expected text after startup state is available; default is `90000`.
- `ANDROID_SMOKE_UI_POLL_INTERVAL_MS`: positive milliseconds between UI hierarchy polling attempts; default is `1000`.
- `ANDROID_SMOKE_LOGCAT_LINES`: positive integer line limit for app-process startup logcat.
- `ANDROID_SMOKE_ADB_TIMEOUT_MS`: positive integer timeout for each `adb` command.
- `ANDROID_SMOKE_METRO_HOST`: Metro host checked before launch; default is `127.0.0.1`.
- `ANDROID_SMOKE_METRO_PORT`: Metro port checked before launch; default is `8081`.
- `ANDROID_SMOKE_METRO_TIMEOUT_MS`: positive integer timeout for the Metro preflight check; default is `3000`.
- `ANDROID_SMOKE_REQUIRE_METRO`: set to `false` to skip the Metro preflight and reverse step when validating the bundled APK.
- `ANDROID_SMOKE_CLEAR_APP_DATA`: set to `true` to run `pm clear` for the package after APK install and before launch.
- `ANDROID_SMOKE_EXPECT_TEXTS`: comma-separated UI texts expected after launch.

Smoke pass means:

- The dashboard renders `Wallets`, `E2EWalletTypeTest`, `Send`, and `Receive`.
- Or, when `ANDROID_SMOKE_EXPECT_TEXTS` is set, the focused app UI contains the documented expected texts for that fixture.
- Logcat has no `AndroidRuntime` crash.
- Logcat has no React Native runtime error.
- Electrum connection does not block app startup.
